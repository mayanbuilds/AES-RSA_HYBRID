This module demonstrates symmetric encryption using AES-GCM (Galois/Counter Mode). AES-GCM provides authenticated encryption, guaranteeing both secrecy (confidentiality) and protection against tampering (integrity). A single shared key encrypts and decrypts the data along with a fresh initialization vector (IV) generated for every operation. If even a single bit of the ciphertext or IV is altered, decryption immediately fails.

Understanding AES-GCM Authenticated Encryption:

Symmetric Key: Both parties share the same secret key. AES is fast and suitable for bulk data.
Galois/Counter Mode (GCM): Unlike older block cipher modes (like ECB or CBC), GCM computes a 16-byte cryptographic authentication tag alongside the ciphertext. Decryption will verify this tag mathematically before releasing any plaintext.
Initialization Vector (IV): A 12-byte nonce (number used once) must be uniquely randomized for every message under the same key. The IV does not need to be secret and is sent in plaintext alongside the ciphertext.

This module demonstrates asymmetric encryption using RSA-OAEP (Optimal Asymmetric Encryption Padding) with a 2048-bit modulus and SHA-256 hash. In public-key cryptography, anyone can encrypt using the public key, but only the holder of the private key can decrypt. Due to mathematical constraints and OAEP padding overhead, RSA cannot encrypt arbitrary bulk data and is strictly capped at 190 bytes.

Why RSA is only for small payloads:

Payload Limit Formula: For a 2048-bit modulus (256 bytes) using RSA-OAEP with SHA-256 (hash length hLen = 32 bytes), the maximum message size is:
max_bytes = k - 2*hLen - 2 = 256 - (2 * 32) - 2 = 190 bytes.
Performance & Randomization: RSA modular exponentiation is hundreds of times slower than AES. Furthermore, OAEP padding adds randomized salt, meaning encrypting the exact same message twice generates completely different ciphertexts. Real systems use RSA solely to exchange small secret session keys, giving rise to hybrid cryptosystems (Part C).

This module implements a minimal hybrid cryptosystem combining the speed of AES-256-GCM symmetric encryption with the key-exchange capability of RSA-2048-OAEP. The sender generates a one-time session key, encrypts arbitrary-sized payload data with AES-GCM, and encrypts only the 32-byte session key with the receiver's RSA public key. The receiver decrypts the session key using their private key and subsequently decrypts the payload.

How This Mirrors Real-World Security (TLS):

This mirrors the idea behind Transport Layer Security (TLS): slow asymmetric cryptography protects a small session key and fast symmetric encryption protects the bulk data. (Modern TLS 1.3 negotiates that key with ephemeral Diffie-Hellman instead of encrypting it with RSA, but the hybrid principle is the same.)

Container Anatomy
SPKI PUBLIC CONTAINER
RFC 5280 / X.509
Format Role: Universal Public Key Container (X.509 Certificates)
PEM Header: -----BEGIN PUBLIC KEY-----
Metadata: AlgorithmIdentifier OID (e.g. rsaEncryption)
Payload: BIT STRING encloses raw RSAPublicKey (Modulus n, Exponent e)
Security: Non-sensitive. Safe for public distribution and TLS certificates.
Active SPKI PEM Output
PKCS#8 PRIVATE CONTAINER
RFC 5208 / RFC 5958
Format Role: Standard Private Key Container (Algorithm-Independent)
PEM Header: -----BEGIN PRIVATE KEY-----
Metadata: Version INTEGER (0) + AlgorithmIdentifier OID
Payload: OCTET STRING encloses full RSAPrivateKey (n, e, d, p, q, dP, dQ, qInv)
Security: High Sensitivity / Secret. Supports optional encryption on disk.
